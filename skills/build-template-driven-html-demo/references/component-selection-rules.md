# 组件自动选择规则

AI 根据业务任务和所选模板自动决定组件，不向对话人确认普通设计细节。模板决定组件的视觉语言；本文件决定何时使用哪类组件。

## 选择原则

| 业务任务 | 默认组件 | 适用条件 |
|---|---|---|
| 浏览、比较多条同构记录 | 表格 | 字段稳定、需要排序筛选或横向比较 |
| 快速扫读少量记录 | 卡片列表 | 每条记录有明显摘要、封面或主操作 |
| 查看一个对象的完整信息 | 详情页 | 内容多、有独立地址、包含历史或多个子区块 |
| 在当前上下文查看或轻量编辑 | 抽屉 | 完成后需要回到原列表，内容不超过一个主要任务 |
| 短小且必须聚焦的确认或填写 | 弹窗 | 删除、提交、完成确认，或少量字段输入 |
| 非阻塞结果反馈 | Toast | 保存成功、筛选已应用、操作失败等短反馈 |
| 创建或编辑结构化数据 | 表单 | 有字段、校验、提交和取消；复杂表单可分组或分步 |
| 同一对象的并列信息分区 | 标签页 | 分区平级且切换不会改变业务进程 |
| 有固定先后次序的任务 | 步骤条 | 下一步依赖上一步，并需展示完成进度 |
| 枚举状态或风险等级 | 标签 / 徽标 | 颜色之外必须同时显示文字 |
| 趋势、构成或对比 | 图表 | 图形能比数字或表格更快表达关系；同时提供关键数值 |
| 知识问答或智能体协作 | 连续对话工作区 | 问题存在上下文、来源依据、继续追问或把回答用于后续任务 |
| 全局或模块切换 | 顶部或侧边导航 | 沿用所选模板的导航骨架；每个全局导航项对应一个完整独立页面视图 |

## 决策顺序

1. 先遵守开发文档明确指定的跳转、弹窗、抽屉或操作方式。
2. 未指定时，判断用户是在“浏览比较”“查看细节”“输入提交”还是“确认后果”。
3. 选择完成任务所需的最小组件组合，不为了展示模板而堆叠表格、图表或弹窗。
4. 将组件映射到所选模板已有的 tokens、DOM 范式和交互函数；禁止从其他模板临时拼入不一致样式。
5. 检查桌面网页常用视口下的信息密度、层级和操作可发现性。

## 常见边界

- 能在抽屉中完成的一次轻量查看或编辑，不额外建立详情页；需要深链接、历史记录或多区块时使用详情页。
- 详情页或详情抽屉的主体是完整业务内容，元数据只作为辅助。若入口承诺“查看详情”，至少显示对象特有的正文、字段分组、过程、结果或其他足以支撑下一步操作的内容，不能只有标题、时间和状态。
- 弹窗只承载一个明确任务。长表单、复杂配置和多步骤操作不得塞进小弹窗。
- 生成、分析或计算产生的大段结果优先在当前页面的稳定结果区呈现，并紧邻编辑、保存、引用、导出或继续处理等真实后续动作；弹窗只适合短确认、少量输入或必须打断当前流程的信息。
- Toast 不承载必须阅读或必须选择的信息；重要错误应在对应字段或页面区域持续显示。
- 表格操作较多时保留一个主操作，其他操作进入行菜单；危险操作必须有清晰后果说明。
- 图表不是装饰。如果不能对应明确指标、维度和数据，就改用数字卡或表格。
- 页面跳转由业务层级决定，不因单文件限制而取消；可用同一 HTML 内的视图切换或 hash 路由模拟。
- 全局导航不得用长页面锚点滚动模拟“换页”。单文件 Demo 在任何时刻只显示一个顶层页面视图，未选视图必须完全隐藏。

## 智能问答界面

当需求是知识问答、政策咨询或智能体协作时，默认把对话作为页面主体，而不是“上方表单 + 独立结果卡 + 右侧来源栏”。首次进入显示助手说明和少量场景化建议问题；提问后形成连续的用户/助手消息流，输入区保持在对话区底部，并允许继续追问。

依据与当前回答放在一起，以可点击来源条目打开原文摘要或来源说明。回答后的复制、引用到文书、继续处理等动作紧邻该回答，并且必须真实生效。提供“新对话”以清空当前会话，但不得误删其他页面的 mock 工作数据。所有聊天组件继续使用所选模板的颜色、间距、按钮、弹窗和反馈语言，不能另起一套产品风格。

当契约要求多次使用、返回查看或恢复上下文时，提供历史会话入口；每条历史会话能打开自己的完整消息内容，并能继续当前会话。若契约只是一次性问答，不为了模仿成熟产品强行增加历史模块。

## 自动补全范围

AI 可以直接决定：栅格与留白、控件尺寸、按钮摆放、普通图标、表格列宽、抽屉宽度、弹窗尺寸、hover、focus、过渡效果、空态版式和非关键辅助文案。这些决定必须遵守模板包，不需要逐项询问。

如果差异实质上涉及权限、审批、业务状态、数据修改、强制确认或不可逆后果，它就不是组件问题，应回到开发文档契约处理。

## 交互最低要求

- 可点击控件必须产生可见结果；这条要求同样适用于中间预览。未完成的功能省略，或明确禁用并说明原因。
- 按钮名称就是动作承诺：“保存”必须真实更改当前 mock 状态，“导出”必须在前端产生可下载文件，“刷新”必须更新可见数据或时间，“新增”和“编辑”必须先提供可填写内容。不得只弹出“成功” Toast。
- 没有实际结果的控件应删除、禁用并说明原因，或改成不会误导的非交互元素。
- 灰色样式不等于禁用。原生控件使用 `disabled`；自定义控件必须同时阻止鼠标和键盘触发，并让人能理解不可用的原因。
- 搜索、筛选、排序、分页或视图切换只实现开发文档需要的部分，并真实作用于 mock 数据。
- 表单具备必填、格式和业务条件校验；失败时保留用户输入。
- 弹窗和抽屉支持关闭按钮、遮罩或明确取消路径；键盘用户能够退出。
- 状态变化后，同一数据在卡片、列表、详情和统计中的展示保持一致。
- 模板中的示例控件只是风格和构造参考，不能因为模板有导出、审批或邀请组件，就在业务文档未要求时自动加入这些功能。
- 具有业务前置条件的按钮只在条件满足时启用；禁用时要能从页面文案理解原因。
- 顶层页面切换后同步导航选中态、面包屑和页面标题，并将内容滚动位置归零；返回时默认保留该页筛选和表单状态，除非开发文档另有要求。
