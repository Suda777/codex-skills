# Demo 独立审查清单

生成者不得自行充当唯一审查者。必须启动一个独立 subagent，以只读方式检查正确契约、选定模板包、生成的 `index.html` 和静态控件清单。审查者必须在真实浏览器中逐项操作；阅读源码、静态清点和自动检查都不能代替实际点击。审查者不直接修改文件，只报告证据；生成者修复后，原审查者复查问题。

## 审查范围先判定

- 生成的客户 Demo：以对话人确认的开发文档和后续明确修正为业务契约。
- 模板包或模板样例：以 `manifest` 和明示样例范围为准，不套用无关的示例开发文档。
- 开始前先记录本次审查的产物类型与事实源，若不能确定则先向生成者求证，不自行假定。

## 严重级别

- `BLOCKER`：核心流程走不通、关键规则错误、数据自相矛盾、可见启用控件无效或用成功 Toast 伪装结果、不是单文件离线运行，或明显偏离所选模板。
- `MAJOR`：必做需求遗漏、重要交互或文案错误、明显布局破损、关键可访问性问题。
- `MINOR`：不影响主流程的视觉、文案或边界问题。

存在任何未解决的 `BLOCKER` 或 `MAJOR` 不得交付；`MINOR` 可在不影响主流程时明确披露。

## 1. 业务覆盖

- [ ] 每个必做页面都能从明确入口进入。
- [ ] 每个可见的全局或侧边导航项都打开一个有实际内容的完整页面，没有占位 Toast、死链接或“待开发”入口。
- [ ] 每个必做字段、指标和状态都有对应展示。
- [ ] 每个 `action_id` 都有可点击入口、结果和反馈。
- [ ] 每条 `must` 规则至少有一个可观察证据。
- [ ] 每条主要 `journey` 已从真实入口完整走到终态；不是只分别证明其中按钮可以点击。
- [ ] 权限、状态流转、计算和完成条件与契约一致。
- [ ] 开发文档明确排除的能力没有被包装成已实现功能。
- [ ] 核心业务对象的列表摘要和完整详情均已实现；详情包含对象特有的实质内容，不只是元数据或所有对象共用的泛化段落。

## 2. 数据与交互

- [ ] 已运行 `scripts/inventory_controls.py index.html`，并人工补全脚本运行后动态生成的控件。
- [ ] 控件清点覆盖所有页面以及点击后才出现的弹窗、抽屉、菜单、行操作、动态新增记录和条件状态。
- [ ] 已记录按钮、链接、表单、切换控件、自定义交互角色以及可点击卡片或行的总数、可用数和按设计禁用数；所有可见且启用的控件均已逐项真实触发。
- [ ] 按设计禁用的控件均有明确原因，不会呈现为可操作的假入口。
- [ ] 每个控件的实际结果与名称一致；没有用“已保存”“已导出”“已刷新”等成功 Toast 掩盖未发生的动作。
- [ ] 统计卡、图表、列表和详情使用一致的 mock 数据口径。
- [ ] 搜索、筛选、排序和分页按可见数据真实工作。
- [ ] 新增、编辑、删除、提交或状态变更能同步更新相关视图。
- [ ] 新增、生成或保存的对象能够从预期入口重新找到并打开；重新打开后正文、字段和状态与刚才的结果一致。
- [ ] 编辑后保存会保留新版本；编辑后取消不会污染原版本；关闭重开、切页返回后符合契约规定的持久范围。
- [ ] 来源、引用、上游或下游入口打开真实相关内容；没有目标的入口已省略，或处于有明确原因的禁用状态。
- [ ] 表单校验能够阻止无效提交，并给出就近、可理解的错误提示。
- [ ] 弹窗、抽屉、菜单和页面跳转可以正常打开、关闭和返回。
- [ ] 任何时刻只显示一个顶层页面；不能通过上下滚动进入另一页。
- [ ] 页面切换后导航选中态、面包屑和页面标题同步，内容滚动位置归零；返回时页面内已有操作状态按要求保留。
- [ ] 正常态以及契约要求的空态、异常态或临界情况可被触发。
- [ ] 连续点击、取消后重试和重复打开不会造成明显状态错误。
- [ ] 已覆盖“关闭后立即重开”“连续提交”“切页后返回”等容易触发竞态或陈旧状态的快速操作。
- [ ] 如存在导出入口，会实际产生非空、字段合理且与当时 mock 数据一致的可下载文件；如存在新增、编辑、邀请等入口，会先显示输入界面并在提交后更新 mock 数据。
- [ ] 有前置条件的业务按钮在条件不满足时不可执行，且页面能说明原因。
- [ ] 对重复行、卡片或会话，已选择至少两个内容、状态或类型不同的实例，确认详情和动作均绑定正确对象；不得只测试默认第一条。

## 3. 文案与事实边界

- [ ] 页面标题、字段名、状态名和按钮名与开发文档一致。
- [ ] 同一概念全站使用同一称谓。
- [ ] 成功、失败、空态和确认提示说明清楚后果与下一步。
- [ ] 操作名称、颜色和层级与真实后果一致；危险样式只用于真实删除、覆盖或不可逆操作，局部移出、停用、取消参与或关闭不会被误解为删除。
- [ ] 页面没有堆叠开发说明、显而易见的操作提示或重复的 Demo/Mock 小字；必要边界说明集中、克制且不干扰主要任务。
- [ ] 没有真实客户、人员、联系方式、内部账号或敏感数据。
- [ ] 没有把 mock、占位能力或未接入系统描述成真实上线能力。
- [ ] 没有复制参考网站的品牌、Logo、专有文案或受保护素材。

## 4. 模板一致性与网页质量

- [ ] 实际使用的是指定 `template_id`，没有混入其他模板的标志性样式。
- [ ] 导航、卡片、按钮、表格、表单、弹窗、抽屉和状态组件遵守该模板 tokens。
- [ ] 字号层级、间距、圆角、阴影、边框和色彩保持系统性。
- [ ] 主操作清晰，危险操作不与普通操作混淆。
- [ ] 页面没有因固定大高度、过量留白或松散卡片显得空洞；核心内容区、输入区、结果区和操作区的密度与所选模板一致。
- [ ] 常用电脑浏览器视口下没有遮挡、截断、横向溢出或文字挤压。
- [ ] 窄屏网页下的菜单、遮罩、切页和主操作可用；列表日期、长标题、徽标、输入区、弹窗或抽屉底栏没有断裂、难读或横向溢出。本 Skill 不把原生桌面端布局作为交付目标。
- [ ] 交互状态包含必要的 hover、focus、disabled、selected 和 loading 表现。

## 5. 单文件与离线运行

- [ ] 交付物只有一个必要的 `index.html`，无需安装或启动服务。
- [ ] CSS、JavaScript、mock 数据、SVG 和必要图片均已内嵌。
- [ ] 源码中没有 CDN、远程图片、网络字体、API、外部脚本、外部样式或本地旁文件依赖。
- [ ] 通过 `file://` 打开后核心流程正常，控制台无阻塞错误。
- [ ] 刷新、回到默认入口和“恢复演示数据”行为符合生成规则。

## 6. 基础可访问性

- [ ] 页面结构有正确标题层级和语义区域。
- [ ] 表单控件有可关联标签，图标按钮有可理解名称。
- [ ] 键盘可以到达并操作核心控件，焦点状态可见。
- [ ] 弹窗和抽屉打开后焦点合理，关闭后返回触发位置；支持 Escape 退出。
- [ ] 状态和风险不只靠颜色表达，文字对比度足够。
- [ ] 动画不会阻止操作，并尊重 `prefers-reduced-motion`。

## 审查输出格式

```markdown
# 独立审查报告
- 结论：PASS | FAIL
- 输入：契约文件、template_id、index.html
- 产物类型：客户 Demo | 模板样例
- 覆盖统计：必须需求通过数 / 总数；可见控件总数 / 实测数 / 禁用数

## 问题
- [BLOCKER] 标题
  - 证据：页面、控件、规则 ID 或复现步骤
  - 期望：契约或模板规定的行为
  - 实际：当前行为

## 已通过的核心路径
1. 入口 -> 操作 -> 状态变化 -> 在相关页面重新找到结果 -> 后续动作或下游联动

## 剩余风险
- 无，或列出无法在静态 Demo 中验证的真实系统能力
```
