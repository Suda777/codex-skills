# 单文件 Demo 生成规则

## 输入与结果

唯一生成公式：

```text
已确认的开发文档内部契约 + template_id 对应模板包 -> index.html
```

输出必须是一个可直接双击打开的 `index.html`。它以 mock 数据演示开发文档中的页面、业务逻辑和交互，同时保持所选模板的布局、视觉 tokens、组件造型和动效语言。

## 优先级

发生冲突时依次遵守：

1. 开发文档中的明确业务要求；
2. 已由对话人确认的假设；
3. 当前模板包的 `manifest`、tokens、组件和交互范式；
4. 本 Skill 的通用默认规则。

模板只决定“怎么呈现”，不得覆盖页面范围、字段、数据关系、按钮结果、状态流转、权限或计算规则。业务内容不得为了套进模板而删减；模板缺少所需组件时，使用该模板的 tokens 和构造方式补齐同风格组件。

示例开发文档只用于它所属的前向测试，不得成为其他 Demo 或模板样例的业务约束。当前对话人后续明确修正的内容高于旧示例或旧假设。

## 生成步骤

1. 读取完整内部契约，建立需求到页面、数据、动作和规则的覆盖映射。
2. 确定稳定的最终输出路径。默认使用当前工作区的 `deliverables/html-demos/<project-slug>/index.html`；临时源文件进入任务专用构建目录，不得写入或改造 `assets/templates/`。
3. 只加载选定 `template_id` 的模板包，读取其 `manifest`、页面骨架、tokens、组件示例和交互约定。
4. 先建立实体和关联正确的 mock 数据，再实现页面和动作；不得用互不关联的随机数字伪装业务关系。
5. 将页面内容装入最合适的模板组件。遵循组件选择规则，不机械复制参考网页的信息架构。
6. 为每个 `action_id` 实现真实可见的响应，包括导航、弹窗、抽屉、校验、数据更新或反馈。
7. 为每个全局导航项建立唯一顶层页面视图，且任何时刻只激活一个。
8. 按 `journeys` 走通跨页面任务链，确认创建或修改后的对象能在相关列表、详情、统计或下游结果中再次看到。
9. 把 HTML、CSS、JavaScript、mock 数据、内联 SVG 和必要的内嵌图片合并到最终 `index.html`。
10. 交给独立 subagent 按审查清单检查；修复阻塞问题后再交付。

## 单文件与离线约束

- 不使用 npm、构建工具、服务器、框架运行时或安装步骤。
- 不引用 CDN、网络字体、远程图片、远程脚本、远程 CSS、API 或在线地图瓦片。
- CSS 放入 `<style>`，JavaScript 和 mock 数据放入 `<script>`；图标优先使用内联 SVG。
- 在 `file://` 环境中仍能完成核心流程；不得依赖 `fetch()` 读取本地旁文件。
- 页面之间的跳转使用同文件视图切换或 hash 路由；刷新后的默认入口清晰可用。
- 全局导航只用于页面切换，不得指向同一长页面中的章节锚点。未激活页面使用 `hidden` 或等效机制完全移出布局和可访问树。
- 页面内容过长时允许在当前视图内滚动，但不得通过滚动进入另一个顶层页面。
- 页面切换后同步 `aria-current`、面包屑和页面标题，将内容滚动位置归零，并默认保留每页已输入的筛选或表单状态。
- mock 数据默认只在内存中变化。只有开发文档要求刷新后保留，才使用 `localStorage`，并提供恢复演示数据的入口。

## 模板保真规则

- 颜色、字体栈、字号层级、间距、圆角、阴影、边框、导航结构、组件状态和动效均取自当前模板包。
- 不在同一 Demo 中混用多个模板的标志性风格。
- 来源为“仅参考”的网页只能提炼设计规律；不得复制其品牌、Logo、专有文案、受保护图片或整段源码。
- 来源代码允许复用时仍要去品牌化，并遵守模板包记录的许可证和署名要求。
- 开发文档没有图片需求时，不为追求相似度随意添加与业务无关的大图。

## 业务与文案规则

- 所有数字、筛选项、状态、图表和统计必须由同一份 mock 数据推导或明确标为固定演示指标。
- mock 数据使用匿名、合成且语义一致的名称；不得包含真实客户、人员、账号或内部数据。
- 按钮名称说明动作结果，状态名称保持全站一致。
- 未提供的非关键文案可以补写，但不得补写政策结论、业务承诺、真实成效或未经确认的能力。
- 未实现的后台能力应做可解释的前端模拟，不得暗示已经连接真实系统。
- 核心业务对象必须有对象特有的完整内容。列表或卡片可以显示摘要，但点击“查看”“详情”或同等入口后，不得只重复标题、日期、状态等元数据，也不得让不同对象机械复用同一段正文。
- 生成型能力必须产出足以支持下一步演示的实质内容；如果页面承诺保存、引用、编辑、导出或汇总该结果，后续动作必须使用刚生成的同一份内容，而不是另造一份无关 mock。
- 页面文案只保留使用者完成任务所需的信息。不要在每页重复“前端演示”“Mock 数据”“点击进入完整页面”“规划中”等开发说明；确有必要说明演示边界时，放在交付说明或一个克制、统一的位置。

## 信息密度与完成度

- 信息密度跟随所选模板和业务任务，不用固定大高度、过量留白或松散卡片填充页面。内容少时收紧容器，内容多时建立清晰分组与滚动区域。
- 对页面中的核心组件单独完成布局推敲，例如对话输入区、数据表、详情区、生成结果、编辑器和主操作区；不能只保证“一眼能看”，还要检查对齐、层级、间距、按钮位置和长文本表现。
- 辅助文案只解释真实的不确定性、前置条件或操作后果。显而易见的界面说明、实现状态和开发术语不进入产品界面。
- 宽屏与窄屏都是网页布局。窄屏不能靠整体缩小解决；需要重新排列栅格、操作区和列表字段，并检查日期、长标题、徽标、抽屉底栏和输入区是否断裂或溢出。

## 控件与动作完整性

- 生成前建立控件动作矩阵，至少记录：所在页面、控件名称、来源需求、前置条件、实际动作、数据变化、可见反馈、受影响视图、失败或禁用状态。覆盖每个可启用的按钮、链接、表单、切换控件、自定义交互角色以及可点击卡片或行。
- 矩阵必须覆盖所有可到达页面，以及打开弹窗、抽屉、菜单、新增记录或切换状态后才出现的动态控件。
- 这个矩阵是 AI 内部的实现与审查工具，不要拿普通组件细节去询问不懂技术的对话人。
- 中间预览可以只实现部分范围，但每个显示为可用的控件都必须实际可用。未完成能力应省略，或禁用并就近说明原因。
- 可观察结果可以是换页、打开或关闭容器、数据变化、筛选结果、就近校验错误或下载文件。取消的正确结果是关闭且不修改数据；不要为每个动作强制添加 Toast。
- 导出在无后端 Demo 中使用 Blob 或 data URL 生成真实本地文件；文件非空、字段合理，且与点击时的 mock 状态一致。无法产生文件时不显示导出入口。
- 新增、编辑、邀请、提交等动作必须先收集必要输入并校验，再更新内存 mock 数据；不得在点击入口后直接伪造成功。
- 保存或提交后，重新打开目标对象必须看到刚才的结果；编辑后的保存版本要保留，取消必须恢复到进入编辑前的版本。若动作会影响多个视图，统一从同一份 mock 状态重新渲染。
- 来源、引用、查看上游或查看下游等关系型动作必须到达真实相关内容；没有来源目标时应省略入口，或禁用并就近解释，不能打开空页面或无关页面。
- 操作名称、视觉层级和真实后果必须一致。只有真实删除、覆盖或不可逆操作使用危险文案与危险样式；移出某个集合、停止参与某项计算或关闭展示必须明确说明作用范围。
- 刷新、扫描、重置和同步类动作必须产生可见的数据、计数、状态或时间变化。
- 只有真实完成后才显示成功反馈。Toast 用于说明已发生的结果，不是动作本身的替代品。
- 重复控件共用一个处理器时，仍要使用不同数据实例验证目标绑定正确，例如每一行“查看详情”都打开对应记录。
- 不能只用第一条或默认对象证明重复交互正确。至少选择内容、状态或类型不同的代表性实例，确认每个实例显示自己的详情、动作作用于正确对象、下游联动使用正确数据。
- 列表、详情、统计、图表、通知和筛选状态必须来自同一份 mock 业务状态，或明确标注为不与当前台账联动的固定演示指标。变更数据后重新计算所有受影响的计数、空态、过滤结果和可执行条件。
- 交付审查前运行 `scripts/inventory_controls.py index.html`，把输出交给独立审查者。静态清点只能发现遗漏线索，不能证明交互正确。

## 完成标准

只有同时满足以下条件才可交付：核心演示路径可完整点击；所有可见且启用的控件都有真实且可观察的效果；必须页面、字段、动作和规则全部覆盖；模板视觉一致；一个 HTML 文件离线运行；控制台无阻塞错误；独立审查没有未解决的 `BLOCKER` 或 `MAJOR`。

清理临时文件后再次确认最终绝对路径存在，且最终目录只有必要的 `index.html`。交付链接、应用内打开目标和向对话人报告的路径必须完全一致；不得交付临时源文件、模板目录文件或依赖仍在运行的 localhost 地址。
